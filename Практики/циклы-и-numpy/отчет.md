# Циклы и NumPy, 10 задач

Код в `compare.py`. Запуск: `python compare.py`. Одна задача: `python compare.py 4`.

Время через `time.perf_counter`, 3 прогона, записывал минимум. Массив один, `default_rng(42)`, создаётся до замера. После замера проверка `isclose` / `allclose`.

## Задача 1. Сумма

`n` только `10^5`, `10^6`, `10^7`.

| n | цикл, мс | NumPy, мс | ускорение |
| --- | --- | --- | --- |
| 100000 | 7.20 | 0.04 | 172× |
| 1000000 | 79.47 | 0.95 | 84× |
| 10000000 | 939.18 | 8.48 | 111× |

Больше 10× уже на `n = 10^5`, это самый маленький размер из условия. Дальше ускорение не растёт вместе с n: на миллионе 84×, на десяти миллионах 111×. Оба варианта всё равно проходят весь массив, цикл делает это в Python, `a.sum()` в C. `a.sum()` короче, одна строка.

## Задача 2. Среднее и std

`n = 10^6`. Цикл 168 мс, NumPy 5.5 мс, ускорение 30×. Разница по mean `3.4e-18`, по std `1.0e-14`, порог `1e-12` проходит. В цикле сумма, сумма квадратов и формула, в NumPy два вызова. Второй вариант короче и его проще проверить глазами.

## Задача 3. sin(x) + x^2

`n = 10^6`. Цикл 158 мс, NumPy 17 мс, ускорение 9×. Список занял 30.95 МиБ, один массив NumPy 7.63 МиБ, список примерно в 4 раза больше: там объекты и указатели, в массиве 8 байт на число. `np.sin(a) + a**2` читается сразу, цикл собирает список по одному элементу.

## Задача 4. Clip

`n = 10^6`. Изменилось 658924 элемента. Цикл 175 мс, `np.clip` 1.1 мс, ускорение 161×. В цикле `for` и два `if`. `np.clip(a, 0, 1)` делает то же без них.

## Задача 5. Сумма по строкам

Матрица `(100000, 10)`. Цикл 266 мс, `m.sum(axis=1)` 1.6 мс, ускорение 164×. В цикле 7 строк с индексами `i` и `j`, в NumPy одна строка. `axis=1` прямо говорит «по строкам», в цикле это надо вычитывать.

## Задача 6. Среднее по столбцам

Та же матрица. Цикл 427 мс, NumPy 7.7 мс, ускорение 56×, результаты совпали. NumPy это `m - m.mean(axis=0)`, среднее само растягивается на все строки. В цикле два прохода и индексы по строкам и столбцам. Поддерживать одну строку проще.

## Задача 7. Максимум и индекс

`n = 10^6`. Оба нашли `5.007235`, индекс `42665`. Цикл 94 мс, NumPy 1.2 мс, ускорение 76×. В цикле надо самому хранить значение и индекс. `a.max()` и `a.argmax()` короче, и по ним сразу видно, что ищется.

## Задача 8. Фильтр x > 0

`n = 10^6`, отобрано 499690 чисел. Цикл 93 мс, NumPy 10 мс, ускорение 9×. По памяти разница заметнее: список 19.22 МиБ (40.3 байта на элемент), массив 3.81 МиБ (8 байт). Ускорение меньше, чем на сумме, потому что оба варианта ещё и собирают новый результат. Массив при этом сильно компактнее.

## Задача 9. Модуль на месте

`n = 10^6`. Цикл с `if` и `a[a < 0] *= -1`. Цикл 152 мс, NumPy 15 мс, ускорение 10×, отрицательных после прохода нет. Строка с маской короче цикла. Разрыв по времени небольшой: маска `a < 0` сама занимает память, это не чистый проход без лишних массивов.

## Задача 10. Маска -1 < x < 1

`n = 10^6`, в интервале 682890 чисел. Цикл 150 мс, NumPy 13 мс, ускорение 11×. В Python пишется `-1 < x < 1`, это нормально читается. В NumPy нужны скобки: `(a > -1) & (a < 1)`. Без скобок у меня сразу `TypeError`, потому что `&` срабатывает раньше сравнений.
